# راهنمای ویزاردها — نسخهٔ ۱٫۲

از منوی **Connections → Manage connection profiles** پروفایل اتصال بسازید.
هر پروفایل شامل تنظیمات دیتابیس و FTP است و امکان ویرایش و Clone با نام جدید دارد.
در تسک فقط پروفایل انتخاب می‌شود؛ دکمهٔ New connection profile پنجرهٔ modal ایجاد پروفایل را باز می‌کند.

رمز دیتابیس و FTP مستقل‌اند: متغیر محیطی، Manual رمزگذاری‌شده با DPAPI ویندوز، یا Runtime Prompt.
رمز Manual در زمان تعریف دریافت می‌شود. رمزگذاری به کاربر ویندوز وابسته است؛ برای اجرای پروژه
با کاربر یا سیستم دیگر باید رمز دوباره وارد شود. Remember در اجرای پروژه، پروفایل اجرای فعلی
شامل نام کاربری و رمز را به‌صورت رمزگذاری‌شده ذخیره می‌کند.

تست دیتابیس و FTP دو کلید مستقل دارند. Next تست اتصال انجام نمی‌دهد. اگر تست ناموفق باشد،
ذخیره با تأیید کاربر ممکن است. خواندن کاتالوگ و ساختار ستون‌ها عملیات جداگانه است.

ترتیب ویزارد تسک:

1. انتخاب پروفایل و تست اختیاری اتصال‌ها.
2. انتخاب عملیات و جدول از کاتالوگ، یا تایپ نام جدید برای مقصد. در UNLOAD می‌توان SELECT داد.
3. انتخاب فایل، ZIP یا dbmeta و تنظیم batch، Dataset، فشرده‌سازی و رمز ZIP.
4. ساختار CSV با ستون‌های انتخاب‌شدهٔ پیش‌فرض؛ امکان تعیین Encoding هر ستون و Trim.
5. نمایش و ویرایش اسکریپت ساخت جدول و Tablespace؛ گزینهٔ ایجاد جدول فقط در صورت عدم وجود.
6. مرور و نمایش Query یا Cards و ذخیرهٔ تسک.

UNLOAD با Query و خروجی Delimited از خواندن جریانی SQL استفاده می‌کند؛ Native از DSNUTILU.
تبدیل‌های ستون برای CSV هستند و روی فایل باینری Native اعمال نمی‌شوند. برای ترکیب Encodingهای
مختلف، کدپیج‌ها باید با ASCII سازگار باشند. NULL با رشتهٔ خالی متفاوت نگهداری می‌شود.

کنار خروجی یک فایل `.dbmeta` شامل ساختار، Encoding، تنظیمات CSV، اسکریپت قابل ویرایش،
اطلاعات کاتالوگ و Cards ساخته می‌شود. Cards برای LOAD باینری مهم‌اند: محل ستون‌ها، نوع داده
و NULL را تعریف می‌کنند. مقصد و DD هنگام LOAD بازتنظیم می‌شوند.
اسکریپت تولیدشده بازسازی قابل ویرایش است؛ موارد پیشرفته مثل Identity، Partition، Index،
LOB و Grant باید بازبینی شوند. تعریف کامل کاتالوگ برای این بررسی در metadata نگهداری می‌شود.

ویزارد اجرای پروژه modal است: ابتدا Override پروفایل، نام کاربری/رمز و پارامترها؛ سپس پیشرفت
و خطاهای لحظه‌ای؛ در پایان آمار و گزارش متنی قابل ذخیره. تعدادهای اعلام‌نشده توسط Utility
«نامشخص» هستند، نه صفر. گزارش تعداد درج، تعداد خروجی، خطا، زمان و نرخ سطر/ثانیه و سطر/دقیقه دارد.

ZIP و رمزداربودنش تشخیص داده می‌شود. رمز خالی یا اشتباه هنگام LOAD دوباره درخواست می‌شود.
ZIP خروجی در صورت تعیین رمز با AES-256 ساخته می‌شود و metadata را هم دارد. فایل اصلی خروجی
حذف نمی‌شود؛ بنابراین رمز ZIP به‌معنای رمزگذاری فایل CSV باقی‌مانده نیست.
